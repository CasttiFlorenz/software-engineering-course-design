# R07、R08 需求调研报告（待补访谈证据）

负责人为张子原。调研范围为一个班的一次课程作业，覆盖评语追问、漏评与补派。资料来源为[需求调研计划](../research-plan.md)。目前缺少可引用的真人访谈材料，以下产品规则属于待验证假设。

## R07 评语追问

| 待验证假设 | 需要采集的证据 |
| --- | --- |
| 作者在某条评语下追问时，只有该评语的评阅人、教师和助教可见，无关学生不可见。 | 请学生复盘一次遇到含糊评语的过程：当时通过什么渠道澄清、由谁答复、是否希望教师或全班也看到。记录追问与答复的原文形式（脱敏）。 |
| 追问需要挂在具体评语上，并保留评语指向的维度或原文位置。 | 请评阅人描述收到追问时如何找到所指内容，记录是否需要作者指明段落、维度或版本。 |
| 讨论期结束后讨论串只读，评阅关闭后不再变更。 | 请教师或助教说明互评截止后是否还受理评语沟通，超时沟通由谁处理、如何处理。 |

需求和验收场景见 [R07 用户故事](../user-stories/R07.md)。匿名与权限遵循 [R05 用户故事](../user-stories/R05.md)，评语与维度、原文位置的对应关系见 [R06 用户故事](../user-stories/R06.md)。

## R08 漏评与补派

| 待验证假设 | 需要采集的证据 |
| --- | --- |
| 负责人通过按作品统计已收评语数发现漏评，不必逐份人工核对名单。 | 请教师或助教复盘一次漏评处理：怎样知道谁没交评语、发现时距离截止多久、用了哪些表格或群聊记录。 |
| 补派需要记录补派人、时间和原评阅人，补派后作品的有效评语数仍有上限。 | 请负责人说明补派时如何找人和通知，记录补派后是否出现重复评语、当时如何取舍。 |
| 补派后原评阅人迟交的评语不直接生效，由负责人确认采纳或舍弃。 | 请受访者复盘一次原评阅人迟交的情况，记录该评语最终是否被作者看到、由谁决定、是否需要告知作者。 |

需求和验收场景见 [R08 用户故事](../user-stories/R08.md)。评阅量配置与分配规则见 [R04-1](../user-stories/R04-1.md)及 [R04-2](../user-stories/R04-2.md)，处理漏评时的身份查询权限遵循 [R05](../user-stories/R05.md)。

## 访谈纪要

待取得真人访谈材料。计划联合访谈同班一名有互评经历的学生和任课教师或助教，围绕同一次作业复盘。每场访谈记录日期、受访者匿名代号与角色、关键问答、现有流程、遇到的问题和例外；将受访者描述的事实与分析推断分开，标注支持或修正了哪条故事的哪个验收场景。入库前移除姓名、学号、群聊标识以及可识别身份的作业内容。
