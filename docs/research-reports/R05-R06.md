# R05、R06 需求调研报告（待补访谈证据）

负责人为赵晨瑞。调研范围为一个班的一次课程作业，覆盖匿名与权限、给出与收到反馈。资料来源为[需求调研计划](../research-plan.md)。目前缺少可引用的真人访谈材料，以下产品规则属于待验证假设。

## R05 匿名与权限

| 待验证假设 | 需要采集的证据 |
| --- | --- |
| 作者查看反馈、评阅人查看作业时，界面与学生可访问的数据对双方隐藏身份。 | 请学生分别从作者和评阅人的角度复盘一次互评，记录在哪一步看到了哪些信息、是否曾因此调整反馈。询问文件名、正文署名和通知是否暴露过身份。 |
| 负责人处理错派、漏评或争议时，按本次作业的授权查询身份。 | 请教师或助教复盘一次异常处理，记录当时需要知道谁的身份、由谁查询、查询以外还能如何解决。 |

需求和验收场景见 [R05 用户故事](../user-stories/R05.md)及 [Issue #11](https://github.com/CasttiFlorenz/software-engineering-course-design/issues/11)。

## R06 给出与收到反馈

| 待验证假设 | 需要采集的证据 |
| --- | --- |
| 评价维度、所指位置和具体建议能帮助作者判断改动。涉及整篇的反馈应允许标记其范围。 | 请学生复盘一条真正采纳和一条没能用上的反馈，记录评语形式、查找原文的步骤、最后如何修改。请评阅人描述哪些建议只能针对全文。 |
| 原文定位应保留与被评阅版本的关联。 | 请有修订经历的学生展示如何在旧稿或新稿查找评语所指位置，记录使用的文件格式、定位失败的情形及现有做法。 |

需求和验收场景见 [R06 用户故事](../user-stories/R06.md)及 [Issue #12](https://github.com/CasttiFlorenz/software-engineering-course-design/issues/12)。

## 访谈纪要

待取得真人访谈材料。优先请有作业互评经历的学生及任课教师或助教复盘同一次作业，可和组员联合访谈。每场访谈记录日期、受访者匿名代号和角色、关键问答、现有流程及例外。将受访者描述的事实与分析推断分开，标注支持或修正了哪条故事的哪个验收场景。入库前移除姓名、学号、群聊标识以及可识别身份的作业内容。
