# [用户故事] 作者在含糊评语下追问评阅人

## 用户故事

作为收到互评反馈的作业作者，我想在指定评语下追问澄清，以便准确理解评阅人的修改建议并决定如何修改。

## 调研依据

- 来源：[R07 调研报告](../research-reports/R07-R08.md#r07-评语追问)及 [11 月 27 日访谈摘要](../research-reports/R07-R08-interview-notes.md#r07-评语追问)。
- 发现：访谈答复显示，学生收到含糊评语时缺少统一澄清渠道，只能私下询问，教师和助教也不掌握澄清过程；作者需要把追问挂在具体评语上，由该条评语的评阅人回复。以下场景按「仅作业作者与该条评语的评阅人可见、双方匿名」编写，追问对教师和助教的可见范围、讨论期时长仍待确认。

## 验收标准

### 场景 1：作者发起追问

- **Given** 学生 A 已登录，是作业 V1 的作者，评阅人 B 对 V1 提交的评语已发布，且讨论期未结束。
- **When** A 在该评语下提交追问「你指的是第二段哪一条论据？」。
- **Then** 追问出现在该评语的讨论串中，原评语内容保持不变。
- **And** B 可以读到此追问；学生端页面与接口响应均不包含 A 的姓名、学号或可直接关联到 A 的账号标识。

### 场景 2：评阅人回复追问

- **Given** 评阅人 B 已登录，该评语下已有作者 A 的追问，讨论期未结束。
- **When** B 在该讨论串中提交回复。
- **Then** 回复出现在同一讨论串中，A 可以读到。
- **And** A 的学生端页面与接口响应均不包含 B 的姓名、学号或可直接关联到 B 的账号标识。

### 场景 3：无关学生访问讨论

- **Given** 学生 C 已登录，既不是作业 V1 的作者，也不是该条评语的评阅人。
- **When** C 打开该讨论串的链接或对应接口。
- **Then** 系统拒绝读取，响应中不包含讨论内容与参与者身份。

### 场景 4：讨论期结束后提交追问

- **Given** 学生 A 是该作业的作者，该评语所在的讨论期已结束。
- **When** A 尝试在同一评语下提交新的追问。
- **Then** 系统拒绝并提示讨论期已结束，原有讨论串转为只读，已有内容不被修改。
