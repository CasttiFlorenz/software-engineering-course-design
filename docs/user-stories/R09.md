# R09：修订与回应

## 用户故事

作为一名收到匿名互评意见的学生，我想逐条记录评语的采纳情况、填写处理理由，并关联修订稿中的对应段落，以便清晰展示自己的修改过程和处理意见。

## 调研依据

- **来源：** 学生互评作业经历。
- **发现：** 学生收到多条评语后，容易遗漏部分修改建议；对于不认同或只能部分采纳的意见，缺乏统一的理由记录方式，也难以让教师快速了解具体修改情况。

## 验收标准

### 场景 1：正常完成反馈回应

- **Given：** 学生已收到匿名互评意见，并已进入作品修订阶段。
- **When：** 学生选择某条评语，将其标记为采纳、部分采纳或暂不采纳，填写处理理由，并关联修订稿中的对应段落。
- **Then：** 系统保存评语的处理状态、回应理由及对应修改位置，并将其与修订稿关联，供教师后续查看。

### 场景 2：原文内容被删除

- **Given：** 学生收到的评语针对初稿中的某个段落，但在修订过程中决定删除该段落。
- **When：** 学生将该评语标记为已处理，并说明删除该段落的原因。
- **Then：** 系统允许学生注明原段落已删除，保留原始评语及其对应的初稿内容，不强制要求关联新的修改段落。

### 场景 3：部分采纳评语

- **Given：** 学生收到一条包含多项修改建议的评语，但认为其中只有部分建议适合自己的作品。
- **When：** 学生将该评语标记为部分采纳，填写处理理由，并关联实际修改的段落。
- **Then：** 系统保存部分采纳状态、处理理由及修改位置，使教师能够了解学生具体采纳了哪些建议。

## 关联与待确认

- **关联需求或 Issue：** R09 修订与回应。
- **待确认事项：** 学生是否必须对每一条互评意见作出回应，才能提交修订稿；部分采纳是否需要进一步说明具体采纳的部分。
