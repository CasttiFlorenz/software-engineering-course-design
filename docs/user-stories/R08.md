# [用户故事] 负责人发现漏评并补派评阅任务

## 用户故事

作为负责课程互评的教师或助教，我想及时看到未完成的评阅任务并补派给其他评阅人，以便每份作品在评阅截止前收到预定数量的反馈。

## 调研依据

- 来源：[R08 调研报告](../research-reports/R07-R08.md#r08-漏评与补派)与[需求调研计划](../research-plan.md)。脱敏访谈证据待补。
- 发现：待确认负责人目前怎样发现漏评、补派通过什么方式进行，以及补派后原评阅人迟交的评语如何处理。以下场景按「按作品统计已收评语数提示漏评、补派留日志、重复评语由负责人确认」的初稿假设编写。

## 验收标准

### 场景 1：负责人查看漏评

- **Given** 教师 T 拥有该课程的互评管理权限，作业设定每份作品由 2 人评阅，学生 A 的作品当前只收到 1 条已提交评语，评阅期已过半。
- **When** T 打开该作业的互评进度页。
- **Then** A 的作品出现在漏评列表中，显示已收 1/2 条，并标出尚未提交评语的评阅人数量，T 可按本次作业的授权查询具体身份。

### 场景 2：负责人补派评阅任务

- **Given** A 的作品仍缺 1 条评语，评阅期未结束，学生 D 尚有评阅余量且未评阅过该作品。
- **When** T 把 A 的作品补派给 D。
- **Then** D 的待评任务中出现该作品并标记为「补派」，可开始评阅。
- **And** 系统记录补派时间、操作人和原未交评阅人，该作品的有效评语目标仍为 2 条。

### 场景 3：补派后原评阅人迟交

- **Given** A 的作品原评阅人 E 未交评语，任务已补派给 D 且 D 已提交评语，随后 E 在评阅截止前提交了评语。
- **When** 系统收到 E 的评语。
- **Then** 该评语进入「待负责人确认」状态，不直接计入有效评语数，也不会自动展示给作者 A。
- **And** T 可选择采纳 E 的评语或保留 D 的评语，作品最终有效评语数不超过 2 条，选择结果记入分配日志。

### 场景 4：没有可补派的评阅人

- **Given** A 的作品仍缺 1 条评语，其余学生均已满评阅额度或已经评阅过该作品。
- **When** T 尝试补派。
- **Then** 系统拒绝补派并提示没有可用的评阅人，该作品的漏评状态保持待处理，T 可据此延长评阅期或调整评阅人数。

### 场景 5：非负责人访问互评进度

- **Given** 学生 C 已登录，既不是该课程的教师，也不是助教。
- **When** C 打开该作业的互评进度页或调用对应接口。
- **Then** 系统拒绝读取，响应中不包含评阅进度、评阅人身份或分配日志。
