# [用户故事] 学生在互评中匿名参与

## 用户故事

作为参与课程作业互评的学生，我想在评阅分配给我的作业和查看自己收到的反馈时与对方互相匿名，以便减少同学关系对反馈的影响。

## 调研依据

- 来源：[需求调研计划 R05「匿名与权限」](../research-plan.md)。计划要求核实作者、评阅人、助教和教师各自需要知道的信息。仓库暂无该调研点的脱敏访谈记录。
- 发现：待确认现有互评流程在哪些环节会暴露身份，以及教师和助教处理错派、漏评或争议时是否需要查询真实身份。以下验收场景基于学生双向匿名、身份查询按本次作业授权的初稿假设。

## 验收标准

### 场景 1：评阅人打开分配给自己的作业

- **Given** 学生 B 已登录，处于评阅期，且被分配评阅学生 A 的作业提交。
- **When** B 打开该评阅任务。
- **Then** B 可以看到该任务的匿名编号和用于评阅的作业内容。
- **And** 学生端页面和接口响应均不包含 A 的姓名、学号或可直接关联到 A 的账号标识。

### 场景 2：作者查看已发布的反馈

- **Given** 学生 A 已登录，B 对 A 的作业所写的反馈已发布。
- **When** A 打开自己的反馈详情。
- **Then** A 可以阅读该反馈，学生端页面和接口响应均不包含 B 的姓名、学号或可直接关联到 B 的账号标识。

### 场景 3：无关学生通过链接访问互评记录

- **Given** 学生 C 已登录，既不是该作业的作者，也未被分配评阅该提交。
- **When** C 直接访问该提交的评阅详情链接或对应接口。
- **Then** 系统拒绝读取，响应中不包含作业内容、反馈或参与者身份。

### 场景 4：按本次作业权限核查身份

- **Given** 该作业的任课教师拥有身份查询权限，参与课程的助教仅拥有互评进度查看权限。
- **When** 教师和助教分别查询同一条互评记录的作者与评阅人身份。
- **Then** 教师可以核对该作业的作者和评阅人，助教仍可查看互评进度，但身份查询被拒绝且响应不包含身份信息。

## 关联与待确认

- 关联需求或 Issue：R05。R04 的评阅分配决定评阅人的访问范围，R06 的反馈展示及 R07 的追问沿用本故事的匿名规则。
- 待确认事项：是否采用全程双向匿名；助教处理哪些情况时需要身份查询权限；文件名、正文署名及附件元数据中的身份信息由谁处理，如何验收。
