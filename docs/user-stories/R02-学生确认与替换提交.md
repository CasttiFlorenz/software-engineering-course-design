# [用户故事] 学生确认并替换最终提交版本

## 用户故事

作为提交课程作业的学生，我想在提交后获得可核对的回执，并在截止前按规则替换错交文件，以便确认评阅采用的是正确版本，避免漏交或错交。

## 调研依据

- 来源：围绕电子作业提交、提交确认和版本管理进行了实际调研，采用文献查阅方式了解在线作业提交与学生使用体验。
- 发现：学生会担心电子提交是否成功以及是否发送了正确文件，也希望获得能够证明作品已经提交和接收的明确回执。因此，系统需要给出正式回执并标明当前最终版本。

## 验收标准

### 场景 1：学生成功提交作业

- **Given** 学生已登录并属于该课程，作业处于可提交状态，当前时间早于截止时间，所选文件符合该作业配置的格式和大小限制
- **When** 学生上传文件并确认提交
- **Then** 系统保存该文件并将其标记为当前最终版本，生成显示作业名称、提交编号、提交时间、文件名、版本号和“已提交”状态的回执，同时将作业列表中的提交状态更新为“已提交”

### 场景 2：学生在截止前替换错交文件

- **Given** 学生已经提交第 1 版文件，当前时间早于截止时间，且该作业允许替换提交
- **When** 学生上传第 2 版文件并确认替换
- **Then** 第 2 版被标记为当前最终版本并生成新的提交回执，第 1 版保留为历史版本但不会被分配给评阅人，页面明确显示第 2 版是将被评阅的版本

### 场景 3：截止后提交未获许可

- **Given** 作业截止时间已过，教师或助教没有为该学生开放迟交权限
- **When** 学生尝试提交新文件
- **Then** 系统拒绝本次提交并说明作业已截止，已有最终版本及其提交时间保持不变；如果此前没有最终版本，提交状态仍为“未提交”

## 关联与待确认

- 关联调研点：R02 提交与封存
- 关联需求：
- 待确认事项：截止前是否允许无限次替换；迟交权限由教师还是助教审批；历史版本保留期限和可见角色；提交回执是否需要提供下载功能。
