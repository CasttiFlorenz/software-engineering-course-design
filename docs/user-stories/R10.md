# R10：修订验收

## 用户故事

作为一名负责检查学生修订成果的教师，我想对照查看学生的初稿、修订稿、互评意见及回应记录，以便快速定位修改内容，判断学生是否合理处理了评阅意见。

## 调研依据

- **来源：** 教师作业批改与互评验收经历。
- **发现：** 教师检查修订成果时，需要反复对照初稿、评语和修订稿。当学生修改内容较多或未采纳部分建议时，难以快速定位具体修改位置，也不容易了解学生的处理理由。

## 验收标准

### 场景 1：正常查看修订成果

- **Given：** 学生已提交修订稿，并完成互评意见的回应记录。
- **When：** 教师进入作品修订详情页面，选择查看某条互评意见。
- **Then：** 系统展示该意见对应的初稿内容、评语、学生回应理由及修订稿中的关联段落，方便教师对照检查修改情况。

### 场景 2：学生未采纳某条评语

- **Given：** 学生已将某条评语标记为暂不采纳，并填写了处理理由。
- **When：** 教师查看该条评语的修订验收信息。
- **Then：** 系统保留并展示该评语、学生的处理状态及理由，不将未采纳的评语直接判定为修订失败，供教师结合实际情况判断。

### 场景 3：查看原文与修订稿差异

- **Given：** 学生已提交修订稿，系统保存了作品的初始版本。
- **When：** 教师选择查看作品的版本对比。
- **Then：** 系统并排展示初稿与修订稿，并突出显示修改或删除的内容，方便教师快速定位作品变化。

### 场景 4：查看评语讨论记录

- **Given：** 学生曾针对某条匿名互评意见发起追问，评阅人已经作出回复。
- **When：** 教师进入该条评语的修订详情页面。
- **Then：** 系统展示该评语对应的匿名讨论记录及学生最终的处理结果，帮助教师了解学生修改时的参考依据。

## 关联与待确认

- **关联需求或 Issue：** R10 修订验收。
- **待确认事项：** 教师是需要逐条确认反馈的处理情况，还是只需要对整份修订稿作出总体验收；是否需要增加通过、待修改等验收状态。
