# [用户故事] 作者按评价维度和原文位置查看反馈

## 用户故事

作为收到互评反馈的作业作者，我想看到每条已发布反馈对应的评价维度、所指的原文位置和改进建议，以便知道要改哪里、为什么要改以及可以怎么改。

## 调研依据

- 来源：[R06 调研报告](../research-reports/R05-R06.md#r06-给出与收到反馈)及 [11 月 27 日访谈摘要](../research-reports/R05-R06-interview-notes.md#r06-给出与收到反馈)。
- 发现：待确认作者收到笼统评语时能否找到对应内容，以及评阅人是否需要写整篇反馈。以下场景使用虚构样例，暂按每条反馈关联一个评价维度，定位到被评阅版本的一处原文或明确标为整篇。

## 验收标准

### 场景 1：评阅人给出可定位的改进建议

- **Given** 处于评阅期，评阅人 B 已登录并获分配评阅作业 V1，该作业设有「论证充分性」维度。
- **When** B 选择该维度和 V1 第二段的一处原文，填写「这里用个例推断整体趋势，建议补充班级层面的统计数据」，并提交反馈。
- **Then** 系统确认提交成功，并保存评价维度、V1 版本、所选原文位置和建议正文。

### 场景 2：作者从已发布的反馈定位到被评阅版本

- **Given** 学生 A 是作业作者，V1 第二段的反馈已发布，且 A 已提交修订版 V2。
- **When** A 在反馈列表中打开标有「论证充分性」的该条反馈并选择定位原文。
- **Then** 系统展示完整建议，并定位到 V1 中评阅人选定的原文，即使 V2 的段落顺序已经变化。

### 场景 3：评阅人提交适用于整篇的反馈

- **Given** 处于评阅期，评阅人 B 已登录并获分配评阅该作业，作业设有「结构清晰度」维度。
- **When** B 选择该维度，将反馈范围设为整篇，填写「建议在开头加一段概述，说明下文三个部分的关系」并提交。
- **Then** 系统保存该反馈。反馈发布后，作者能看到「整篇」标记、评价维度和建议正文。

### 场景 4：评阅人提交空反馈

- **Given** 评阅人 B 已登录并获分配评阅该作业，已选定评价维度和反馈范围，建议正文只有空白字符。
- **When** B 提交反馈。
- **Then** 系统提示填写建议正文，保留已选的维度和范围，且不新增已提交的反馈。
