# [用户故事] 负责人发现漏评并补派评阅任务

## 用户故事

作为互评负责人（教师或助教），我想及时发现漏评并给其他评阅人补派任务，以便每位应评作业都能按时收到足够数量的评价。

## 调研依据

- 来源：调研点 R08「漏评与补派」访谈纪要（张子原整理，对象：任课教师 T1、助教 A1，已脱敏）
- 发现：
  - 观察到的事实：目前靠助教手工核对表格统计谁没交评语，发现漏评往往已临近截止；（待确认：核对频率与漏评发现时点）
  - 观察到的事实：补派通常在群里临时找人认领，补派后原评阅人又迟交评语时，会出现同一作业评语数量超过预期、需要人工取舍的情况；（待确认：超量评语的取舍规则）
  - 推断：缺少漏评预警和补派记录，会导致分配状态不透明、返工量大。
  - 待确认：补派后原评阅人迟交的评语是采纳、丢弃还是并存；漏评判定阈值（缺几条算漏评）。

## 验收标准

### 场景 1：系统提示漏评

- **Given** 负责人已登录，互评进行中，某作业的应获评语数为 3，当前只有 1 条已提交，且已过约定的评阅中期检查点
- **When** 负责人打开漏评看板
- **Then** 该作业出现在漏评列表中，显示已收 1/3 条及未交评阅人的数量
- **And** 看板在测量条件下（100 份作业、30 名评阅人）加载时间不超过 3 秒

### 场景 2：负责人补派评阅任务

- **Given** 负责人已登录，某作业存在漏评，且存在尚未满额的可补派评阅人
- **When** 负责人为该作业补派 2 名评阅人
- **Then** 被补派的评阅人收到该作业的评阅任务，且每人任务列表中标注"补派"
- **And** 补派记录（时间、补派人、原漏评人）保存在分配日志中可供查询

### 场景 3：原评阅人在补派后迟交

- **Given** 某作业的原评阅人 X 被判定漏评后任务已补派给 Y，评阅人 X 随后在评阅截止前提交了评语
- **When** 系统收到评阅人 X 的迟交评语
- **Then** 该评语进入待处理状态，不直接计入该作业的有效评语数
- **And** 负责人收到提示，可选择采纳或丢弃该评语；无论采纳与否，最终有效评语数、分配日志均可核对

### 场景 4：无可补派评阅人

- **Given** 某作业存在漏评，但所有候选评阅人均已满额或不可分配
- **When** 负责人尝试补派
- **Then** 系统拒绝补派并提示无可补派评阅人，漏评记录保持待处理状态

## 关联与待确认

- 关联需求或 Issue：调研点 R08；与 R04「互评分配」的分配规则需衔接
- 待确认事项：漏评判定阈值与中期检查点时点；补派后原评阅人迟交评语的采纳规则；补派是否影响原评阅人的考核
